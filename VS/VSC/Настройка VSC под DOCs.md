**Да, VS Code отлично умеет компилировать C# проекты!** 

Чтобы делать всё удобно через графический интерфейс (из меню и кнопок, без ручного ввода команд в терминал), Microsoft сделала официальный набор инструментов **C# Dev Kit**. С ним в VS Code появляется такое же дерево проекта («Обозреватель решений»), как в большой Visual Studio.

Вот пошаговая инструкция, как с нуля собрать всё только мышкой.

---

### Шаг 1. Устанавливаем C# Dev Kit в VS Code

1. Открой **VS Code**.
2. На панели слева нажми значок **четырёх кубиков** (Расширения) или комбинацию `Ctrl` + `Shift` + `X`.
3. В строке поиска напиши:  
   `C# Dev Kit`
4. Найди расширение **C# Dev Kit** (от автора *Microsoft*) и нажми синюю кнопку **Install** (Установить).  
   *(Вместе с ним автоматически подтянется базовый плагин C#)*.

---

### Шаг 2. Создаем проект библиотеки классов через меню

1. Нажми сочетание клавиш **`Ctrl` + `Shift` + `P`** *(или нажми Шестерёнку внизу слева → «Палитра команд...»)*.
2. В появившуюся вверху строку начни писать по-английски:  
   `.NET: New Project...`  
   и нажми **Enter**.
3. В выпадающем списке шаблонов кликни на **Class Library** (Библиотека классов).
4. Напиши имя проекта, например: `TFlexMacros`, и нажми **Enter**.
5. Выбери папку на диске, где проект будет лежать, и нажми кнопку выбора папки.
6. В правом нижнем углу появится синее окно — нажми **Open** (Открыть проект).

Слева на панели появится вкладка **«Обозреватель решений»** (Solution Explorer) — точно такая же, как в классической Visual Studio.

---

### Шаг 3. Подключаем DLL-библиотеки T-FLEX DOCs мышкой

1. В панели слева разверни свой проект `TFlexMacros`.
2. Найди пункт **Зависимости** (Dependencies / Ссылки).
3. Нажми по нему **правой кнопкой мыши** и выбери:  
   **«Добавить ссылку на проект / файл...»** (Add Reference...).
4. Выбери вариант **«Обзор файла...»** (Browse).
5. Откроется стандартное окно Windows. Перейди в папку установки T-FLEX DOCs (например, `C:\Program Files\Топ Системы\T-FLEX DOCs [версия]\Program\`).
6. Зажми клавишу `Ctrl` и выдели мышкой нужные файлы:
   * `TFlex.DOCs.Model.dll`
   * `TFlex.DOCs.Model.Macros.dll`
   * `TFlex.DOCs.Model.References.dll`
   * и другие сборки TFlex.
7. Нажми кнопку **«Добавить»** (Add).  
Они тут же появятся в списке зависимостей твоего проекта.

---

### Шаг 4. ЕСЛИ НУЖНО ВНЕШНИЕ! Пример: Подключаем NLog и System.Text.Json (через меню)

1. В «Обозревателе решений» нажми **правой кнопкой мыши прямо по имени проекта** (`TFlexMacros`).
2. В появившемся контекстном меню выбери:  
   **«Manage NuGet Packages»** (Управление пакетами NuGet) или **«Add Package...»**.
3. В появившуюся сверху строку поиска введи: `NLog` и нажми Enter. В списке нажми на **NLog** и выбери последнюю версию.
4. Повтори то же самое для: `System.Text.Json`.

---

### Шаг 5. Вставляем код и компилируем через кнопку

1. В списке файлов открой `Class1.cs` (можно переименовать его в `Macro.cs`).
2. Вставь туда весь код макроса из окна T-FLEX DOCs.
3. **Как скомпилировать без терминала:**
   * В «Обозревателе решений» нажми **правой кнопкой мыши по имени проекта** (или по самому верхнему пункту Solution).
   * Выбери команду **«Собрать» (Build)**.
4. Внизу откроется панель вывода, и через пару секунд появится заветная надпись:  
   `Build succeeded` (Сборка завершена успешно).

---

### Пояснение: почему так?
* **C# Dev Kit** превращает легковесный VS Code в полноценную среду разработки. Он берёт на себя всю скрытую работу: сам генерирует файл конфигурации сборки (`.csproj`), прописывает пути к DLL и компилирует код по нажатию правой кнопки мыши, избавляя тебя от необходимости вручную писать команды в терминале.
* Теперь в этом же проекте у тебя работает **Cline**: агент видит все библиотеки T-FLEX DOCs, понимает их внутренние функции и пишет макросы без ошибок типизации!

## Вопрос:   
Два момента: 
1. Комплект для разработчиков C# что-то хочет от меня (настройку?). 
2. Я не вижу обозревателя решения (вижу проводник, но не вижу там Зависимостей)

## Ответ:
Оба момента связаны между собой и решаются буквально за пару кликов! 

На твоем экране сработали две штатные защиты VS Code:
1. **Синяя плашка в самом верху: «Ограниченный режим» (Restricted Mode)** — VS Code заблокировал запуск расширений, так как пока «не доверяет» этой папке. Из-за этого C# Dev Kit просто не может запуститься и показать «Обозреватель решений».
2. **C# Dev Kit просит войти в аккаунт Microsoft** — это требование лицензии плагина (вход бесплатный).

Вот пошаговый план, как всё включить:

---

### Шаг 1. Включаем доверие к папке (Снимаем ограничение)

1. Посмотри на самый верх экрана — там висит синяя полоса с текстом: *«Ограниченный режим предназначен для безопасного просмотра кода...»*.
2. Нажми на подчеркнутое слово **«Управление»** прямо на этой синей полосе.
3. Появится окно с вопросом о доверии. Нажми большую синюю кнопку **«Да, я доверяю авторам»** (Trust folder and enable all features).
4. Синяя плашка пропадет, и расширения начнут оживать.

---

### Шаг 2. Авторизуемся в C# Dev Kit

C# Dev Kit от Microsoft бесплатен для индивидуального использования, но требует входа под любой учетной записью Microsoft:

1. Прямо по центру экрана в карточке «Подключить учетную запись» нажми синюю кнопку **«Войти»**.  
   *(Или нажми на значок человечка в кружочке в самом низу слева).*
2. Откроется браузер: войди под своей учетной записью Microsoft (подойдет любая личная почта `@outlook.com`, `@hotmail.com` или корпоративная).
3. Разреши браузеру передать данные обратно в VS Code.

---

### Шаг 3. Где появится «Обозреватель решений» с Зависимостями?

Как только шаги 1 и 2 будут выполнены, плагин завершит загрузку (в нижней панели сейчас как раз доустанавливаются нужные компоненты):

1. Посмотри в левую колонку **«Проводник»**.
2. Под списком твоих папок появится новый свернутый блок с названием:  
   **«Обозреватель решений» (Solution Explorer)**.
3. Кликни по стрелочке рядом с ним, чтобы развернуть его.
4. Внутри раскрой проект `TFlexMacroTest` — и ты увидишь заветную строчку **«Зависимости» (Dependencies)**!

---

### Пояснение: почему так произошло?
* **Ограниченный режим:** встроенная система безопасности VS Code. При открытии любой новой папки редактор отключает все умные плагины, пока пользователь явно не подтвердит: *«Да, этот код безопасен, его можно компилировать»*.
* **Solution Explorer:** в C# Dev Kit этот блок генерируется только после полной фоновой инициализации компилятора, которая была заблокирована безопасным режимом.

---

### Альтернативный путь: если нет аккаунта Microsoft
Если корпоративная политика запрещает логиниться под учетной записью Microsoft:
* Можно не использовать C# Dev Kit, а подключить библиотеки T-FLEX напрямую через редактирование файла **`TFlexMacroTest.csproj`** (он уже виден у тебя в проводнике). Пара строк текста внутри этого файла подключают любые DLL без регистрации и аккаунтов. Если понадобится этот путь — скажи, я дам готовый шаблон!


## Дополнение
Отличный материал! Этот анонс кардинально меняет логику интерфейса: Microsoft **убрала старый Solution Explorer**, переименовала просмотр зависимостей в **«C# PROJECT DETAILS»** (он чисто информационный, без действий), а **все команды перенесла в обычный проводник на файл `.csproj`** (как раз показано на твоем первом скриншоте `input_file_11.png`).

Вот как теперь выполнять все действия по новым правилам без терминала.

---

### Шаг 1. Где теперь нажимать правой кнопкой мыши?

Забудь про ветку «Зависимости» — теперь всё управление проектом делается через файл **`.csproj`**:

1. Открой обычный **«Проводник»** (самый верхний значок двух листочков слева).
2. Найди файл твоего проекта: **`TFlexMacroTest.csproj`**.
3. Нажми по нему **правой кнопкой мыши**.
4. Появится то самое обновленное меню (как на скриншоте):
   * **`Add Project Reference`** (Добавить ссылку на проект).
   * **`C# Package Management`** (Управление пакетами NuGet).
   * **`Build`** (Собрать / Скомпилировать).

---

### Шаг 2. Подключаем NLog и System.Text.Json (через новое меню)

1. Нажми правой кнопкой мыши по **`TFlexMacroTest.csproj`**.
2. Наведи курсор на **`C# Package Management`** → выбери **`Add Package`** (Добавить пакет).
3. Вверху появится строка поиска: напиши `NLog` и нажми **Enter**, затем кликни по найденному пакету.
4. Повтори то же самое: `C# Package Management` → `Add Package` → напиши `System.Text.Json` → нажми **Enter**.

---

### Шаг 3. Как подключить локальные DLL от T-FLEX DOCs?

Поскольку пункт *«Add Project Reference»* предназначен для связки проектов между собой, локальные сторонние DLL-файлы с диска в .NET всегда подключаются через секцию `<ItemGroup>` внутри самого файла проекта. Это делается за 15 секунд:

1. В проводнике **кликни один раз по файлу `TFlexMacroTest.csproj`** — он откроется как текстовый файл.
2. Заполни файл по шаблону из `Шаблон TFlexMacroTest.csproj.md`
3. Нажми **`Ctrl` + `S`**, чтобы сохранить файл.
4. Теперь загляни в блок слева **«C# PROJECT DETAILS»** → раскрой **Dependencies** → **Assemblies**: ты увидишь, что все библиотеки T-FLEX там появились!

---

### Шаг 4. Компиляция по новым правилам

1. Вставь код макроса в файл `Class1.cs`.
2. В проводнике нажми **правой кнопкой мыши по файлу `TFlexMacroTest.csproj`**.
3. Нажми кнопку **«Build»** (как выделено красным прямоугольником внизу на твоем скриншоте).

---

### Пояснение: почему Microsoft сделала это обновление?
Раньше в VS Code было два дублирующих друг друга дерева: системный «Проводник» с файлами и плагинный «Solution Explorer». Разработчики путались, где создавать файлы, а где компилировать. 

В новом обновлении:
* **Проводник (Explorer)** стал главным центром управления: через правый клик по `.csproj` ты делаешь сборку (`Build`) и управляешь пакетами.
* **C# Project Details** оставили исключительно как информационную панель, чтобы смотреть текущий состав сборок и пакетов.
