## Исходные данные: 
Потребность пользователя. Предположим, в DOCs есть рецептурные технологические процессы плавки. В них описывается какие компоненты шихты (рекомендации и с перечнем замен) необходимо взять со склада, чтобы в процессе плавки получить сплав нужного состава. Однако, каждая плавка - индивидуальна. На складе постоянно присутствуют разные поставки шихты. От партии к партии состав шихты меняется, поэтому с поставкой идет паспорт с точным составом. Поэтому на каждую плавку надо формировать индивидуальные задания, исходя из реального наличия компонентов на складе и их составов.
Задача это непростая, требуется сформировать математическое решение, которое с учетом таблиц угара компонентов, а также невозвратных потерь позволит получить расплав требуемой массы и - главное - требуемого состава.
Берем из техпроцесса исходные данные (надо прикинуть какие), берем необходимые данные из учебников и справочников по литью по угару компонентов (надо прикинуть какие и где их взять).
Берем данные о наличии компонентов на складе (сейчас в DOCs нет такого справочника, надо спроектировать).
Предлагаем пользователю варианты, и предлагаем наилучшие варианты по компонентам.
Добавляем проценты на потери.
Вычисляем точные значения компонентов, сколько надо взять на складе.
Формируем объект задания на плавку (не такого, надо спроектировать).
Формируем печатную форму.
Давай придумаем, какая модель данных понадобится в DOCs. И перечень макросов с описанием что делает. Обязательно задавай вопросы по модели данных - что уже есть готовое, что нужно создавать с нуля.
