# Что нам нужно от Open API T-FLEX CAD 18

Сентябрь 2026. Просьбы идут по порядку важности; к ошибкам приложены шаги и короткий код для воспроизведения.
Файлы деталей и полные задания пришлём по запросу. В примерах `Node(doc, x, y, z)` — наша функция: `new
CoordinateNode3D(doc)` с координатами в мм.

## Как мы расставили приоритеты

Приоритет 1 — то, что останавливает работу без человека: процесс падает, зависает или ждёт ответа в окне. Обхода
нет или он держится на сторожах и перезапусках.

Приоритет 2 — обход у нас есть, но он медленный или ненадёжный и заметно снижает качество моделей.

Приоритет 3 — мелкие ошибки и удобство.

Отдельным списком идёт справка. Правки там, как нам кажется, недорогие, а времени нам они сэкономили бы больше всего.

## Приоритет 1

### 1. Работа без интерфейса

Сейчас наше приложение загружается при старте T-FLEX, по таймеру берёт из папки C#-файл задания, компилирует его в
памяти и пишет ответ в журнал. Очередь держим файлом-замком. Гонки в этой очереди уже давали перепутанные ответы,
теперь в каждое задание кладём метку. В поставке есть `TFlex.CAD.Server.dll` с контрактом `IServer`
(NetNamedPipeBinding, обнаружение по UDP, операции `OpenDocument`, `SaveDocument`, `ExportDocument`), но он не
описан. Не ясно и то, поддерживается ли `InitSession` в отдельном процессе без окна.

Просим описанный способ вызывать Open API из внешней программы с исполнением в потоке CAD, очередь «запрос →
ответ» с идентификатором запроса и условия лицензии для круглосуточной работы и нескольких сеансов на одной машине.

Поймём, что готово, когда внешняя программа сможет открыть документ, выполнить код, сохранить `.grb` и получить ответ
без окна T-FLEX и без нашего приложения внутри процесса.

### 2. Режим без модальных окон

Часть вызовов по умолчанию открывает модальное окно в потоке CAD:

- выгрузка состава изделия (`ExportToXml`, `ExportToCSV`, `ExportToExcel`) при `Silent = false` — это значение по
  умолчанию;
- `ExportToStep` без `ShowDialog = false`: остаётся файл нулевого размера, исключения нет;
- `Document.Close()` у изменённого документа спрашивает «Сохранить?», а выставить `Changed = false` нельзя;
- `Application.OpenDocument` для документа с фрагментами спрашивает про обновление ссылок: флаг
  `OpenDocumentOptions.FileLinksRefreshMode` есть, но по умолчанию режим «спросить».

Windows при этом считает процесс отвечающим, и внешний сторож зависания не видит. Сейчас наш сторож закрывает окна
класса `#32770` через 4 секунды и пишет их заголовки в журнал.

Просим один флаг сессии: вызов, которому нужен ответ пользователя, бросает исключение или берёт значение по
умолчанию. И закрытие документа без сохранения, например `Close(discardChanges: true)`.

### 3. Падение TFlexCad.exe при удалении неудачного скругления

Если `EdgeBlending` не построилось и мы удаляем его через `DeleteObjects`, то примерно на пятнадцатом повторе
процесс TFlexCad.exe завершается:

```csharp
doc.BeginChanges("скругления");
foreach (ModelEdge e in edges)                      // рёбра, на которых скругление радиусом r не строится
{
    EdgeBlending eb = new EdgeBlending(doc);
    eb.Propagate = true;
    eb.OverflowSmooth = true; eb.OverflowCliff = true; eb.OverflowNotch = true;
    eb.AddTopol(e, new EdgeBlending.ConstantBlendAttribute(new Parameter(r)));
    eb.Regenerate(true);
    doc.ApplyChanges();
    if (!eb.GetRegenerationResult(false))
    {
        doc.DeleteObjects(new ObjectArray(eb), new DeleteOptions(true));
        doc.ApplyChanges();                          // примерно после 15 раз процесс исчезает
    }
}
doc.EndChanges();
```

Сейчас каждую попытку делаем в отдельном блоке `BeginChanges … CancelChanges()`, и на тех же деталях падений нет.
Просим исправить: неудачная операция должна отказывать с диагностикой, а не ронять процесс. И описать в справке, как
правильно «попробовать операцию и откатить».

### 4. Расчёт динамики нельзя прервать

`DynamicStudy.Solve()` без обратного вызова считает всю длительность задачи и держит поток CAD. На примере «Маятник»
(3600 с при кадре 0.02 с) это 180 000 кадров: процесс больше 20 минут не отвечал, прервать расчёт было нечем. В это
время расчёт в другом процессе T-FLEX на той же машине 14 минут стоял без загрузки процессора и продолжился через
секунды после завершения первого. Сейчас вызываем `Solve` только с обратным вызовом, который ограничивает кадры и
время, а рискованные расчёты запускаем в отдельном экземпляре T-FLEX и по таймауту завершаем его целиком.

Просим параметр «не больше N кадров или T секунд» у `Solve`, способ прервать расчёт и описание этого в справке.

## Приоритет 2

### 5. Где ошибка и построила ли операция что-нибудь

`Document.Diagnostics` сообщает тип, текст и объект, но не место ошибки. Одна причина даёт каскад: объединение тел,
касающихся ровно гранью, выдаёт «Ошибка генерации тела» и ещё около двадцати сообщений «Операнд для булевой операции
отсутствует». Самопересечение контура тоже приходится искать самим.

Кроме того, ряд операций «успешен» без результата. Каждый такой случай стоил нам прогонов, поэтому сейчас после каждой
операции мы меряем объём и габарит:

| Случай | Что видим |
|---|---|
| Фаска `ChamferAttribute` без `Propagate = true` | операция принята, объём не изменился, ни ошибки, ни диагностики (пример ниже) |
| `GetRegenerationResult(true)` на скруглении закрученной грани | `true`, в диагностике «Геометрия слишком сложная или радиус слишком большой», объём не изменился |
| `GetRegenerationResult` внутри блока изменений | `false` у всех операций, включая нормальные |
| Лофт внутри блока изменений | сразу после `Regenerate(true)` у любого лофта `Geometry.Solid.Length == 0`; тело появляется только после пересчёта документа |
| `Thread.Standard = ...` | присваивание без исключения, стандарт не меняется |
| `Document.CreateVariable(expr)` | возвращает `null`; работает `new Variable(doc, имя, выражение)` |
| `Operation.Color`, `BodyPart.Color`, `ModelFace.Color` | принимаются, но на `ExportToBitmap3D` не влияют |
| `FragmentVariableValue.RealValue = new Parameter(выражение)` | молча игнорируется, фрагмент берёт 0; работает `AttachedVariable` с `IsSet = true` |
| `InterpolatingSplinePath3D` | объект исчезает из документа при `EndChanges` |
| Привязка фрагмента по несуществующему имени ЛСК | исключения нет, фрагмент встаёт по другой ЛСК (подробно в п. 13) |
| `Variable.ErrorState` | `true` при верных значениях и верной модели |
| `CircularArrayOperation` с углом 0° или 360° и `IncludeBase = false` | пустая копия вместо тела |
| Неудачная операция | система её удаляет; следующая ссылка на неё — «Объект был удалён» |

Фаска на кубе 20×20×20:

```csharp
EdgeBlending ch = new EdgeBlending(doc);
foreach (ModelEdge e in verticalEdges)               // четыре вертикальных ребра
    ch.AddTopol(e, new EdgeBlending.ChamferAttribute(new Parameter(2.0), new Parameter(2.0)));
// ch.Propagate = true;   // без этой строки объём остаётся 8000.0, ошибки нет
ch.Regenerate(true);      // со строкой — 7840.0 = 8000 − 4·(2·2/2·20)
```

Просим код ошибки и место внутри операции (ребро, сегмент контура, номер сечения, координаты), отделение
первопричины от следствий, проверку профиля на самопересечение с указанием сегментов и надёжный признак «операция
изменила геометрию» или ошибку «ничего не построено».

### 6. Сопряжения из кода

Сопряжения по граням из кода работают, если элементом брать геометрию грани, как в вашем импортёре SolidWorks.
Фиксация детали, степени свободы и часть типов не работают:

```csharp
// Работает:
Mate m = new Mate(asm);
m.Type = Mate.MateType.Concentricity;
m.Element1 = holeFace.Geometry.Axis;            // TopolReference грани фрагмента в сборке
m.Element2 = pinFace.Geometry.Axis;
m.ReversedDirection = dot(holeAxis, pinAxis) < 0;
// после EndChanges штифт встаёт на ось отверстия

// Не работает:
m.Element1 = holeFace;                           // ModelFace → NullReferenceException (Geometry.Reference == null)
baseFragment.Fixed = true;                       // после EndChanges и Regenerate читается false
new Mate(asm) { Type = (Mate.MateType)13 };      // EndChanges = CompleteError, сопряжения блока пропадают
arm.FixByFragmentLCS("hinge", lcs);
arm.FreedomPropertyContainer.EnableRotationZ = true;   // читается false, связь типа 7 остаётся жёсткой
```

Типов 7, 8, 12, 13 и флагов `ReversedDirection` и `ReversedNormal` нет в справке, хотя тип 7 — самый частый в
«Примерах»: 596 сопряжений из 914. Без фиксации и степеней свободы механизм из кода не собрать.

Просим запись фиксации детали и степеней свободы фрагмента из кода и описание типов и флагов.

### 7. Проверка механизма в движении

Каждое положение механизма мы проверяем так: меняем переменные положения фрагментов, пересчитываем документ и
попарно вызываем `BaseBody.Clash` и `RangeTopol`. Одна поза стоит 0.3–0.6 секунды даже для двух колёс, проверка
сборки из 340 фрагментов (эскалатор: ступени, звенья цепи, рельсы) — 73–77 секунд.

Задачи «Анализа движения», датчики и контакты из кода не создать: у `DynamicStudy`, `Sensor`, `Restraint`,
`PointForce`, `TorqueActuator` только закрытые конструкторы, фабрик нет. Поэтому берём готовую задачу «Маятник» как
шаблон и подменяем в ней деталь. Датчик при этом не перенацелить: `Sensor.SetReference` кладёт ссылку не туда, и
датчик меряет прежнюю точку. Передачи `AngAngTransmission`, созданные из кода между колёсами на шарнирах, держат
отношение, но колёса наклоняются до 7.9°, а ход рейки (`AngLinTransmission`) отличается от заданного на 1–4 %;
диагностика при этом пуста. В вашем примере Gearbox те же передачи решаются точно.

Ещё одно наблюдение. У пары «спусковое колесо + анкер» в двух позах из 21, где зуб лежит на плоской грани палеты,
`Clash` возвращает и касание, и пересечение, а объём пересечения — 0.0000 мм³. Так же ведёт себя вал Ø10 в отверстии
Ø10: пересечение с объёмом меньше 1 мм³. Сейчас проникновением считаем только объём больше 0.001 мм³.

Просим, по убыванию важности:

1. пакетную проверку пересечений для списка пар и положений без пересчёта документа на каждой позе;
2. создание из кода задачи движения, датчиков и контактов тел;
3. пример, как задать колесу вращательную степень свободы из кода, как в примере Gearbox;
4. объяснение, когда пересечение приходит с нулевым объёмом, и способ получить глубину проникновения.

### 8. Запросы к геометрии одним вызовом

Чтобы узнать, выпуклое ли ребро, нам нужны десятки вызовов. Куски и полости тела ищем обходом граней. Точки
проверяем по одной через `ContainsPoint` — по 65 на каждый запретный объём детали.

Тело в памяти нельзя сдвинуть так, чтобы это видели запросы. Шестерня z18, матрица поворота на 90° вокруг оси
колеса (проверена): после `new Body(src).ApplyTransform(m)` точка у зуба на +X по-прежнему внутри, а на +Y — снаружи,
как до поворота. У пары шестерён в 13 положениях `RangeTopol` даёт одно и то же — 0.0554 мм. Поэтому каждое положение
механизма у нас — полный пересчёт документа.

Просим выпуклость ребра и угол между гранями, число кусков и оболочек тела, пакетный `ContainsPoint` (массив точек
→ «внутри / на границе / снаружи») и преобразование тела, видимое запросам.

### 9. Зубчатые колёса из кода

У модуля «Детали машин» нет публичного API, поэтому эвольвенту мы строим сами дугами. Точности нам хватает
(отклонение от эвольвенты не больше 2.1 мкм), но это наш код, который приходится поддерживать. Просим хотя бы
«колесо или пару по модулю, числу зубьев и ширине» и ответ, можно ли пользоваться `CreateGearPair` и
`GearingBatchBuilder`.

## Приоритет 3

### 10. Лофт и 2D-сплайн

Лофт через три и больше сечений тонкого скрученного профиля иногда не строится без понятной причины. Четыре
шестиугольных сечения толщиной 1.5–2.5 мм, каждое следующее повёрнуто и сдвинуто: `LoftOperation` через все четыре
даёт «Тело с ошибками», через крайние два — тело 1305.9 мм³. `SplineConstruction` тоже бывает нестабилен. Обход у
нас есть (`LoftOperation` с `AutoAlignment` по замкнутым сплайнам, свой сплайн из дуг). Просим описать ограничения
и возвращать причину отказа.

### 11. Резьба и спираль

Отверстие Ø10, `Thread` с `Diameter = 10`, `Step = 1.5` и стандартом ГОСТ 8724-2002: `Standard.Name` остаётся
«Резьба упорная ГОСТ 10177-82», в диагностике «Диаметр не содержится в стандарте». `SpiralOperation` с треугольным
профилем 0.44×0.5 мм или квадратом 2×2 мм на оси 10 мм и настройками из «Спираль - резьба.grb» даёт «Ошибка
регенерации», операция удаляется. `Path3DByHelixAxis` тоже не строится. Из-за этого на крепеже нет настоящей резьбы.

### 12. Код с `System.Numerics` в только что запущенном T-FLEX

Первое задание после запуска T-FLEX, которое работает с камерой (`View3D.Orientation` имеет тип
`System.Numerics.Quaternion`), не компилируется: CS0234, «Vector3 отсутствует в пространстве имён System.Numerics».
Сборка ещё не загружена. Обходим отдельным заданием, которое отражением трогает тип `View3D.Orientation`. Просим
методы камеры на `double` и `Point3D`, например `SetCamera(eye, target, up)`.

### 13. Привязка по ЛСК с неверным именем и габарит фрагмента

`SetUniqueName("seat")` даёт имя с суффиксом `seat_2`. Если затем вызвать `FixByFragmentLCSToConnector("seat", t)`,
исключения нет: в диагностике только сообщение «Исходная ЛСК "seat" не найдена. Для привязки выбрана "side_3"», и
фрагмент встаёт по другой ЛСК. Просим в этом случае ошибку.

`Fragment3D.Geometry.AABoundBox` у того же фрагмента, сдвинутого на 100 мм, — X 99.98…100.02: сдвиг прибавлен как
100 метров, поворот не учтён. `FindBoundBox()` у тела даёт верное X 85…115. Просим описать единицы или исправить.

`ConnectorParameters.SetTextValue(...)` возвращает 0, и значение не сохраняется; `SetRealValue` работает.

### 14. Остальное

- Импорт STEP по сетевому пути (`ImportFrom3dCommon.Import(@"\\сервер\папка\файл.stp")`) возвращает `false` без
  причины; с локального диска тот же файл импортируется.
- `OpenDocument(путь, false)` для файла, который пользователь держит открытым, возвращает тот же объект документа, и
  автоматизация может изменить документ пользователя. Нужна независимая копия по умолчанию или признак «уже открыт».
- Приложение, загружаемое при старте, однажды не загрузилось после перезапуска T-FLEX: процесс жив, задания не
  берутся. Модальное окно в конструкторе приложения вешает процесс намертво. Нужно событие «приложение загружено и
  готово».
- Состав изделия: `ToString()` у ячейки возвращает имя типа вместо значения, у параметра «Ревизия» опечатка
  «Revison», кодировки выгрузки не описаны (CSV — UTF-16LE с BOM и `;`, XML — UTF-8 с BOM).
- glTF из невидимого документа пишет камеру как `"rotation":[,,,]`, и файл не читается как JSON; имена узлов пустые.

## Справка: недорогие правки с большой пользой

Самые дорогие наши ошибки случились из-за пробелов в справке.

- Знаки осей стандартных рабочих плоскостей: детали выходили зеркальными.
- Единицы всех величин, включая `AABoundBox` (п. 13).
- Пометить класс `Loft` устаревшим: рабочий класс — `LoftOperation`, на `Loft` мы потратили три захода.
- У каждого метода, который может открыть окно, — пометка и способ это отключить (п. 2).
- Список «признаков успеха», которым нельзя верить (таблица в п. 5).
- Порядок преобразований в группе фрагмента: последнее добавленное применяется первым.
- Перепутанные описания `ConnectorParameters.IsReal` и `IsText`, опечатка `Tolerace` у
  `BSplineSurfaceConstrainedData`.
- Параметры вида `__unnamed000` и члены без описаний, например `MassProperty.FirstMoment` и `OffDiagonal`, единицы у
  `GeometryContact.FindGeometryContacts`.
- Ссылки со страниц классов на примеры из поставки, где эти классы используются: разбор «Примеров» оказался для нас
  лучшим учебником.
- Примеры SDK 18 ссылаются на T-FLEX CAD 16 и собираются только старым MSBuild.
