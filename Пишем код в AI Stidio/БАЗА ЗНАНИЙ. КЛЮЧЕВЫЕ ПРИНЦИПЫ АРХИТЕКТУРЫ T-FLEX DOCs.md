
Для принятия решений всегда основывайся на следующей модели данных и логике работы T-FLEX DOCs:

**1.1. Справочники (Dictionaries/References):**
Это контейнеры для объектов, определяющие базовые правила их организации и поведения.
*   **Тип организации:**
    *   **"Список":** Плоская структура.
    *   **"Дерево":** Строгая иерархия. Один объект может иметь только одного родителя. Родительский объект не хранит прямых ссылок на дочерние.
    *   **"Сложная иерархия":** Сетевая структура. Объект может иметь множество родителей. Связь "родитель-потомок" реализуется через специальный скрытый объект-связку, который может иметь собственные параметры.
*   **Общие свойства (наследуются всеми объектами справочника):**
    *   **Электронная подпись (ЭП):** Поддержка подписания объектов.
    *   **Комплекты разрешений:** Поддержка общих правил доступа.
    *   **Доступ Владельца:** Активация специального набора прав для пользователя, являющегося "Владельцем" объекта.
    *   **Стадии жизненного цикла:** Поддержка состояний объекта (например, "В разработке", "Согласовано"), каждое из которых определяет свой набор разрешений.

**1.2. Типы Объектов (Object Types):**
Конкретные шаблоны данных внутри справочника.
*   **Атрибуты:** Определяют набор параметров (полей) и связей.
*   **Наследование:** Производные типы полностью наследуют параметры и связи родительского типа. Их можно расширять новыми атрибутами или изменять унаследованные свойства.
*   **Событийная модель:** Типы объектов поддерживают события (OnCreate, OnEdit, OnDelete и т.д.), на которые можно назначать обработчики — макросы на C#.
*   **Иерархия типов:** Настройка правил вложенности объектов разных типов внутри одного справочника.

**1.3. Связи (Links):**
Определяют отношения между типами объектов (в том числе из разных справочников).
*   **Размерность:** 1-к-1, 1-ко-многим, многие-ко-многим.
*   **Направленность:** Связь может быть видима со стороны одного или обоих связанных объектов.

**1.4. UI и Представление Данных:**
*   **Диалоги свойств:** Это UI-формы для отображения и редактирования параметров и связей объекта. Диалоги могут быть определены как для всего справочника, так и для конкретного типа объекта.

**1.5. Идентификация и Наследование Сущностей:**
*   Каждая сущность конфигурации (справочник, тип, параметр, связь) имеет уникальный **GUID**.
*   **Наследование — это получение ссылки, а не копии.** Производный тип объекта получает тот же параметр (тот же GUID), что и у родителя, а не его копию. Это ключевой принцип для понимания кастомизации.

**1.6. Модель Управления Доступом (Access Control Model):**
*   **"Владелец":** Системный параметр объекта, ссылающийся на пользователя. Если текущий пользователь является Владельцем, он получает расширенный набор прав.
*   **Принцип сложения доступов:** Итоговые права пользователя на объект являются суммой всех разрешений, полученных им через:
    1.  Текущую стадию жизненного цикла объекта.
    2.  Права Владельца (если он является владельцем).
    3.  Прямо назначенные на объект персональные или групповые доступы.
*   **Приоритет состояний доступа:** Любое действие (просмотр, редактирование, удаление) может иметь три состояния:
    *   **1. Запрещено (высший приоритет):** Перекрывает любое разрешение.
    *   **2. Разрешено (средний приоритет):** Перекрывает "не определено".
    *   **3. Не определено (низший приоритет):** Равносильно запрету.

**1.7. Администрирование и Конфигурация:**
*   Все настройки (создание справочников, типов, связей) производятся в интерфейсе "Управление справочниками".
*   Конфигурацию можно выгрузить в файлы формата **DDX** (zip-архив с XML-описанием структуры) для переноса между базами данных.
