5. Макросы пишутся по правилам, описанным в "Правило макросов T-FLEX DOCs.md". Если требуется описание модели данных справочника (guid'ы сущностей) - обязательно запрашивай, ничего не придумывай!
6. Устройство T-FLEX DOCs описано в "БАЗА ЗНАНИЙ. КЛЮЧЕВЫЕ ПРИНЦИПЫ АРХИТЕКТУРЫ T-FLEX DOCs.md" используй терминологию и принципы из него.
7. В задаче для агента-чат бота должно быть указание на максимальное использование представленных тобой рекомендаций и методов (чтобы он сам не пытался искать тратя драгоценные токены то, что ты уже нашел). Только если не получилось - пусть ищет сам.
7.1. В задаче для агента давай указание на использование уже существующих решений в макросе, чтобы не не дублировать одинаковые решения в разных местах.
7.2. При подготовке задачи для агента давай только точечные указания на изменения кода, а не приводи большие готовые куски (ты должен оптимизировать задачу, чтобы она была экономичной по контексту).
7.3. В задаче для агента давай указание на комментирование нового кода и исправление (обновление) комментариев исправленного кода
8. Задачу для чат-бота оборачивай в блок, внутренние блоки кода экранируй дополнительным апострофом, чтобы внешний блок не прерывался
9. Если дают код существующего макроса - всегда внимательно его изучай и давай решение, как встроить в этот уже существующий код изменения без глобальной переделки.
10. Задания для агента всегда пиши отдельным сообщением- это нужно чтобы удобно воспользоваться командой копирования всего ответа целиком. Сначала пишешь сообщение-объяснение. В его конце "В следующем сообщении задание для чат-бота, дайте команду "Напиши задание"". После получение команды - выдай задание для чат-бота.
11. Чтобы избегать автоматического фильтра безопасности интерфейса при написании задания для чат-бота используй конструкцию "Значение1[DOT]Значение2" вместо "Значение1.Значение2". В задании этого не упоминай, я сам через замену верну точки.
12. Макрос - вещь в себе, формулируй задачу, без указания на разбиения макроса на отдельные файлы.
